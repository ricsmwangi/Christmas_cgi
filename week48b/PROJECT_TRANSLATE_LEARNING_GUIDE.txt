PHASE 1: Understand Process Creation (fork & execvp)
================================================================================

CORE CONCEPT
------------
Your program spawns external processes (argos-translate-cli, espeak) safely
without using the dangerous `system()` function. It does this with fork/exec:

1. fork(): creates a child process (copy of parent)
2. execvp(): replaces child's code with a new program
3. wait/waitpid(): parent waits for child to finish

WHY THIS MATTERS:
- `system()` spawns a shell and is vulnerable to command injection
- fork/exec gives you precise control: no shell expansion, safe argv arrays
- You can redirect I/O (pipes, files) in the child before exec

CODE LOCATION IN project_translate_safe.c:
  Line ~60-80 (child branch in run_command_capture_output function):
    if (pid == 0) {
        dup2(inpipe[0], STDIN_FILENO);
        dup2(outpipe[1], STDOUT_FILENO);
        dup2(outpipe[1], STDERR_FILENO);
        close(inpipe[0]); close(inpipe[1]); ...
        execvp(argv[0], argv);
        _exit(127);
    }

WHAT HAPPENS HERE:
1. fork() created two processes (parent and child)
2. Child is here (pid == 0)
3. dup2() rewires file descriptors so child's stdin/stdout/stderr go to pipes
4. execvp("argos-translate-cli", argv) replaces child's code with argos
5. _exit(127) only runs if execvp fails

PHASE 2: Understand Pipes and I/O Redirection
================================================================================

CORE CONCEPT
------------
Pipes let two processes communicate: one writes, one reads.
Your project uses pipes to:
- Send user's text to argos-translate-cli via its stdin
- Capture argos's output from its stdout
- Capture error messages from its stderr

ANATOMY OF A PIPE:
    int pipe_fd[2];
    pipe(pipe_fd);  // Creates a pipe
    // pipe_fd[0] = read end (file descriptor for reading)
    // pipe_fd[1] = write end (file descriptor for writing)

EXAMPLE DATA FLOW:
    Parent writes to pipe_fd[1] -> data flows through pipe -> Child reads from pipe_fd[0]

CODE LOCATION IN project_translate_safe.c:
  Line ~41-45 (pipe creation):
    int inpipe[2];
    int outpipe[2];
    if (pipe(inpipe) == -1) { perror("pipe"); return NULL; }
    if (pipe(outpipe) == -1) { perror("pipe"); ... return NULL; }

  Line ~65-67 (child redirects I/O):
    dup2(inpipe[0], STDIN_FILENO);    // child's stdin comes from inpipe
    dup2(outpipe[1], STDOUT_FILENO);  // child's stdout goes to outpipe
    dup2(outpipe[1], STDERR_FILENO);  // child's stderr also goes to outpipe

  Line ~90-105 (parent writes to child):
    write(inpipe[1], ptr, len);  // send user's text to child
    close(inpipe[1]);            // signal EOF to child

  Line ~108-125 (parent reads from child):
    read(outpipe[0], buf + used, cap - used);  // read child's output

CRITICAL RULES FOR PIPES:
1. Close file descriptors you don't need in child and parent
   - If parent keeps the read end of inpipe open, parent can't detect EOF
   - If child keeps the write end of outpipe open, it never signals "done"
2. When writing to a pipe, write() will block if pipe buffer is full
3. When reading from a pipe, read() returns 0 at EOF, or blocks if no data
4. Don't use both ends of a pipe in the same process (unless needed)

PHASE 3: Master Dynamic Memory (malloc, realloc, free)
================================================================================

CORE CONCEPT

Your program doesn't know in advance how big the user's input will be or how

PHASE 4: Parse Command-Line Arguments with getopt
================================================================================

CORE CONCEPT
------------
Your program accepts flags like `-i en -o ja -n -p`. The getopt() function
parses these safely and portably.

CODE LOCATION IN project_translate_safe.c:
  Line ~135-158 (main function, getopt loop):
    int main(int argc, char **argv) {
        char src[16] = "en";
        char tgt[16] = "ja";
        int do_speak = 1;
        int persistent = 0;
        
        int opt;
        while ((opt = getopt(argc, argv, "i:o:nph")) != -1) {
            switch (opt) {
                case 'i': strncpy(src, optarg, sizeof(src)-1); break;
                case 'o': strncpy(tgt, optarg, sizeof(tgt)-1); break;
                case 'n': do_speak = 0; break;
                case 'p': persistent = 1; break;
                case 'h':
                default: fprintf(stderr, "Usage: ...\n"); return 0;
            }
        }
    }

HOW getopt WORKS:
- getopt(argc, argv, "i:o:nph")
  - "i:" means -i takes an argument (stored in optarg)
  - "o:" means -o takes an argument
  - "nph" mean -n, -p, -h take NO arguments
  - getopt returns the option character, or -1 when done
  - optarg holds the argument for flags that take one

PHASE 5: Put It Together - run_command_capture_output()
================================================================================

CORE CONCEPT
------------
This is the heart of your project. It combines fork, pipes, and exec:

    1. Create two pipes (input and output)
    2. Fork a child process
    3. Child: dup2 pipes to stdin/stdout, exec external command
    4. Parent: write input to child, read child's output
    5. Parent: waitpid, return captured output

This is a reusable function that safely invokes external commands.

FULL FUNCTION IN project_translate_safe.c:
  Lines ~38-132

STEP-BY-STEP WALKTHROUGH:

STEP 1: Create pipes
    int inpipe[2], outpipe[2];
    pipe(inpipe); pipe(outpipe);
    
    Result:
    inpipe[0] = read end (parent reads FROM child)
    inpipe[1] = write end (parent writes TO child)
    outpipe[0] = read end (parent reads child's output FROM here)
    outpipe[1] = write end (child writes TO here)

STEP 2: Fork
    pid_t pid = fork();
    if (pid == -1) { error handling; return NULL; }
    
    Result: parent and child both continue (pid == child's PID in parent, 0 in child)

STEP 3: Child process setup
    if (pid == 0) {
        // In child
        dup2(inpipe[0], STDIN_FILENO);      // my stdin reads from inpipe
        dup2(outpipe[1], STDOUT_FILENO);    // my stdout writes to outpipe
        dup2(outpipe[1], STDERR_FILENO);    // my stderr also writes to outpipe
        close(inpipe[0]); close(inpipe[1]); close(outpipe[0]); close(outpipe[1]);
        execvp(argv[0], argv);              // become the translator
        fprintf(stderr, "execvp failed: %s\n", strerror(errno));
        _exit(127);                         // only reached if execvp fails
    }

STEP 4: Parent closes child's ends
    close(inpipe[0]);   // parent won't read from this
    close(outpipe[1]);  // parent won't write to this
    
    Result: only parent and child communicate via:
    - inpipe[1]: parent writes, child reads
    - outpipe[0]: child writes, parent reads

STEP 5: Parent sends input to child
    while (len > 0) {
        ssize_t w = write(inpipe[1], ptr, len);
        if (w <= 0) break;
        ptr += w; len -= w;
    }
    close(inpipe[1]);  // tell child: no more input coming (EOF)
    
    Result: child's stdin is fed the input, then receives EOF

STEP 6: Parent reads child's output
    char *buf = malloc(4096);
    size_t cap = 4096, used = 0;
    while (1) {
        ssize_t r = read(outpipe[0], buf + used, cap - used);
        if (r > 0) {
            used += r;
            if (used + 1 >= cap) {
                cap *= 2;
                buf = realloc(buf, cap);
            }
        } else if (r == 0) {
            break;  // EOF from child
        } else {
            if (errno == EINTR) continue;  // interrupted, retry
            perror("read"); break;
        }
    }
    buf[used] = '\0';  // null-terminate
    close(outpipe[0]);

STEP 7: Wait for child and return output
    waitpid(pid, &status, 0);
    return buf;  // caller must free this!
